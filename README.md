# Lookout

macOS의 ‘활성 상태 보기’에서 확인하는 시스템 상태와 프로세스 정보를 메뉴바에서 빠르게 볼 수 있는 앱입니다. 필요한 항목을 선택해 사용하고, 메뉴바 항목을 클릭해 상세 수치와 최근 그래프를 확인합니다.

현재 구현 기준: 2026-10-29 · 버전 `0.6.3a` (build `10`). Swift·SwiftUI·AppKit 기반 macOS 네이티브 앱입니다.

현재 작업본에는 시스템 온도·팬 제어·helper 수동 설정·온도 알림·창 배치 자동 복원이 추가되어 있습니다. 버전은 아직 올리지 않았으며, 이 변경은 기존 GitHub `0.6.3a` Release에 포함되지 않습니다. 다음 배포에서 표시 버전과 내부 build를 함께 증가시켜야 합니다.

## 지원 환경

- macOS Sequoia 15.0 이상
- Apple Silicon (`arm64`) + Intel (`x86_64`) Universal 앱

개발 환경에서 Apple Silicon·macOS 27.0 실행을 확인했습니다. 2026-10-06 사용자 실기기 확인으로 Apple Silicon·Intel Mac 및 macOS 15·26에서도 정상 실행이 보고되었습니다. 기기·OS별 세부 조합과 기능별 검증 범위는 별도로 기록합니다.

## 창 배치 자동 복원

설정 → 모니터링 하단의 `창 배치 자동 복원`에서 켭니다. **기본은 비활성화**입니다. 같은 영역의 `설정 복구` 버튼으로 전용 사용자 세션 도우미를 등록·연결합니다. macOS가 백그라운드 실행 허용을 요구하면 안내 버튼에서 허용하고 돌아오세요. 복구 과정에서 실제 손쉬운 사용 승인이 없으면 설정 화면으로 안내합니다. 그 화면에서 `LookoutWindowHelper`를 허용합니다. 팬 제어용 관리자 helper와 분리된 일반 사용자 권한의 도우미입니다.

설정에는 도우미 연결 상태와 실제 창 접근 결과를 따로 표시합니다. 정상 상태에서는 복구 버튼과 권한 진단을 숨깁니다. 팬 제어와 창 배치 모두 `설정 복구` 버튼과 같은 진행 표시를 사용합니다. 등록·연결·권한 상태를 확인하고 필요한 경우만 복구하며 백그라운드 승인 대기에는 `시스템 설정에서 허용`을 표시합니다. 설정에서 돌아오면 상태를 다시 확인합니다. 권한 거부나 창 조회 확인 실패가 있을 때 표시되는 `권한 확인 결과`에서 현재 도우미의 `AXIsProcessTrusted`와 실제 AX 창 조회 결과를 확인할 수 있습니다. `허용됨 · 실제 창 조회 확인`이면 조회가 성공한 상태이고, `실제 창 접근 거부`이면 설정 스위치가 켜져 보여도 현재 도우미에는 접근이 허용되지 않은 상태입니다. 응답 실패는 권한 거부와 구분합니다. 권한 확인은 창의 위치·크기 쓰기 성공까지 보장하지 않습니다.

업데이트 후 등록·연결에 문제가 생기면 같은 `설정 복구` 버튼을 사용합니다. 정상 등록은 유지하고, helper 변경·등록 누락·실제 연결 오류가 있을 때 등록을 복구합니다. 이 버튼은 macOS의 손쉬운 사용 승인을 대신 부여하지 않습니다. 도우미의 코드 서명이 바뀌어 OS 승인이 유효하지 않으면 시스템 설정에서 다시 허용해야 할 수 있습니다. 기존 앱의 허용 스위치만으로 새 도우미의 권한을 판단하지 않습니다.

활성화 후 첫 정상 배치를 보관하고, 실제 잠자기 알림을 받으면 일반 창의 위치·크기를 다시 저장합니다. 복귀하면 저장 당시의 모든 모니터와 해상도가 일치하고 약 2초간 안정된 것을 확인한 뒤 복원합니다. 대기는 한 번에 최대 약 30초이며, 연결이 더 늦으면 앱/설정으로 돌아오거나 `지금 복원`으로 다시 시도할 수 있습니다. 화면만 꺼지는 경우에는 저장·복원을 시작하지 않습니다.

현재 배치와 이전 정상 배치를 각각 도우미의 로컬 저장소에 보관합니다. 기존 앱의 저장 배치는 한 번 이전하며 원본도 남겨둡니다. 모니터 연결 해제·복원 대기·실패 상태에서는 자동 저장을 막고 기존 배치를 유지합니다. `이전 배치 복원`으로 백업을 사용할 수 있으며, 모니터 구성을 영구적으로 바꾸었거나 새 배치를 기준으로 삼을 때는 확인 후 `현재 배치로 다시 시작`을 선택합니다. 평소 잠자기 전 수동 저장은 필요하지 않습니다.

자동 복원 기준은 최신 배치 1개이며 이전 배치 1개를 백업합니다. 집·사무실처럼 서로 다른 모니터 구성별로 저장본을 자동 선택하는 프로필 기능은 보류했습니다. 현재는 같은 환경에서 잠자기 후 흐트러진 창을 복구하는 데 집중합니다. 모니터 개수·식별자·해상도가 달라지면 복원을 보류하고 저장본을 유지하며, 원래 구성이 돌아오면 다시 복원을 시도할 수 있습니다.

동일하게 실행 중인 앱의 일반 창만 대상입니다. 닫힌 창·전체화면·최소화 창은 건너뛰며 앱 재실행·Spaces 이동·전체화면 복원은 하지 않습니다. 창 식별이 모호하면 임의로 연결하지 않고 기존 배치를 보호합니다. 앱별 Accessibility 지원과 모니터 인식 순서에 따라 일부 창을 복원하지 못할 수 있습니다. 잠자기 직전 조회가 늦거나 실패하면 이미 보관한 배치를 사용하므로 마지막 순간의 이동까지 항상 저장된다고 보장하지 않습니다.

Finder처럼 앱 API의 실행 시각이 없는 경우에는 커널이 제공하는 프로세스 시작 시각으로 동일 실행 여부를 확인합니다. 실행 시각이 없다는 이유만으로 Finder의 일반 창 전체를 저장에서 제외하지 않습니다.

평상시 창 목록을 주기적으로 조회하지 않습니다. 활성화·잠자기·복귀 및 필요한 재시도에서만 작업하며, 창 제목·앱 식별자·위치 정보는 이 Mac의 사용자 설정에만 보관합니다. 외부 모니터 여러 대의 실제 잠자기·복귀 검증은 남아 있습니다.

## 시스템 온도 · M1 Pro 시험 기능

M1 Pro MacBook Pro(14·16인치)에서 CPU·GPU 열 영역의 최고 온도와 왼쪽·오른쪽 팬 RPM을 표시합니다. 설정 → 모니터링의 시스템 온도 이름 옆에서 메뉴바 표시를 `둘 다 / CPU / GPU / 숨김` 중 선택합니다. 기본값은 `둘 다`이며 재실행 후에도 유지됩니다. `숨김`은 메뉴바 온도만 감추고 온도 수집·상세·알림·팬 제어는 유지합니다. 그룹의 짝은 단독으로 표시하며, 다른 표시 항목이 없으면 전체 상세를 열 수 있는 앱 아이콘 하나를 남깁니다. `둘 다`의 메뉴바 단독 항목은 온도계 옆 CPU·GPU 온도를 위아래 두 줄로 표시합니다. 다른 항목과 묶으면 시스템 온도 줄 전체에 `CPU 아이콘 + 온도`와 `GPU 아이콘 + 온도`를 좌우로 배치하고, 두 칸 사이를 넓게 띄웁니다. TEMP·C/G 글자는 표시하지 않으며 숫자는 9pt·고정 폭입니다. `CPU` 또는 `GPU`를 선택하면 단독·그룹 모두 해당 아이콘과 온도 하나만 표시합니다. 마우스 설명도 선택한 온도만 표시하며 경고 색상은 기존처럼 둘 중 높은 온도 단계를 따릅니다. 선택은 메뉴바에만 적용되며 상세·수집·팬 제어·알림 기준은 바꾸지 않습니다. 상세 그래프에는 CPU 하늘색·GPU 주황색 선과 같은 색상 점을 표시합니다. 모드 선택과 helper 활성화는 설정 → 모니터링에서 제공합니다. 온도는 칩 내부 값으로 상판 표면 온도와 다릅니다.

시스템 온도는 **기본 비활성화**이며 설정 → 모니터링에서 사용자가 직접 켭니다. 같은 행의 `팬 설정`에서 제어 모드를 선택합니다. 기존에 저장한 활성·비활성 선택은 유지합니다. 켠 뒤의 기본 제어 모드는 **시스템 자동**이며 조회만으로 팬 속도를 바꾸지 않습니다. 미지원 기기는 시스템 온도를 비활성화하고 기존 모니터링은 유지합니다.

`팬 설정`은 `시스템 자동 / 쾌적 / 적극 냉각`을 제공합니다. 선택 메뉴는 다른 행과 같은 폭이며, M1 Pro 시험 기능 설명은 시스템 온도 행 아래에 표시합니다. 시스템 온도를 켜면 팬 제어 활성화·백그라운드 실행 재허용·갱신/오류 안내와 재시도 버튼도 같은 행의 설명 바로 아래에 모아 표시합니다. 갱신 주기에는 SSD 설명 아래에 최소 5초 수집 간격만 안내합니다. 백그라운드 실행 재허용 안내는 다른 안내문과 같은 11pt입니다.

온도 기반 제어를 처음 사용할 때는 `/Applications`에 설치한 `Lookout.app`에서 시스템 온도 행 아래의 `설정 복구`를 누르고, macOS가 요구하면 `시스템 설정에서 허용`으로 이동해 백그라운드 실행을 허용합니다. 본체 UI 변경만으로 재등록을 요구하지 않습니다. helper 서명·실행 plist가 바뀌었거나 서비스 등록/연결에 문제가 있을 때 `설정 복구`를 안내합니다. 복구 버튼을 누르면 필요한 등록 작업과 읽기 전용 연결 확인을 진행하며, 자동 재등록하지 않습니다. 별도 `LookoutFanHelper`가 관리자 권한으로 실행되며 시스템 자동 모드에서는 연결이 필요하지 않습니다. 모드 변경은 재부팅 없이 적용합니다. 사용자 온도·RPM 입력은 없으며 M1 Pro용 초기 프로필을 사용합니다. 실제 상판 온도·소음 개선과 기종·OS별 제어 동작은 실기기 검증이 필요합니다.

앱 시작·설정 진입·앱 복귀·잠자기 복귀에서는 등록 상태만 확인하며 별도 타이머는 없습니다. 승인 대기 중에는 시스템 설정 안내만 표시하고, 사용자가 허용한 뒤에도 다시 등록하지 않습니다. 연결 오류가 나면 제어를 중단하고 수동 설정 버튼을 안내하며 자동 재등록·연결 복구나 선택 대기를 하지 않습니다. 저장된 팬 모드는 서비스와 권한이 준비된 경우에만 적용합니다. 제어 중 연결 끊김·잠자기·오류에 대한 시스템 자동 복귀와 helper의 안전 처리는 유지합니다.

센서 조회는 기존 수집 루프에서 최소 5초 간격으로 캐시합니다. 온도 기반 제어 중에는 helper가 3초마다 필요한 센서와 두 팬만 확인합니다. 앱은 기존 수집 루프에서 연결을 갱신하며 별도 heartbeat 타이머를 추가하지 않습니다. 종료·잠자기·항목 해제·센서 오류·연결 끊김 시 시스템 제어로 복귀를 요청하고, helper는 15초 연결 만료와 실패 시 재시도·비정상 재시작 복구를 처리합니다. 실제 복귀 확인 실패는 오류로 표시합니다. 다른 팬 제어 앱과 동시에 수동 제어하지 마세요.

읽기 전용 센서 확인은 `build/Lookout.app/Contents/MacOS/Lookout --cooling-probe`, 하드웨어를 대체한 SMC 테스트는 `bash scripts/test-smc.sh`로 실행합니다. helper 설치·자동 제어·비정상 종료 복구의 실제 검증 결과는 [VALIDATION.md](VALIDATION.md)를 확인하세요.

## 모니터링 항목

| 항목 | 표시 정보 | 자동 그래프 |
| --- | --- | --- |
| CPU | 전체 사용률 | 현재 사용률 게이지 + 최근 5분 기록 |
| 메모리 | 앱·Wired·압축·여유 메모리, Swap 사용량·현재 할당량 | RAM 구성 바 또는 구성 게이지 + 최근 5분 기록, 선택 시 Swap 용량 바 |
| SSD | 시작 볼륨의 사용·전체·사용 가능 용량 | 고정 용량 바 |
| 디스크 | 시작 디스크 읽기·쓰기 데이터 속도 또는 IO 횟수 | 읽기·쓰기 라인 |
| 네트워크 | 선택한 인터페이스의 데이터 속도 또는 패킷 수 | 업로드·다운로드 라인 |
| GPU | 전체·렌더링·타일링 사용률, 공유 메모리 | 현재 사용률 게이지 + 최근 5분 기록 |
| 에너지 | 프로세스 추정 전력(W), 소비 상위 프로세스, 잠자기 방지 프로세스 | 추정 전력 라인 |
| 시스템 온도 | M1 Pro CPU·GPU 열 영역 최고 온도·좌우 팬 RPM | CPU·GPU 두 색상 라인, 표현 고정 |

모니터링 항목은 총 여덟 가지입니다. 최초 설치 시 Apple Silicon은 시스템 온도를 제외한 일곱 항목, Intel은 GPU·에너지·시스템 온도를 제외한 다섯 항목이 활성화됩니다. 항목을 끄면 표시와 데이터 수집이 함께 중단되고, 모두 끄면 주기적 수집도 중단됩니다. 설정은 재실행 후에도 유지됩니다.

갱신 주기 기본값은 3초이며 설정에서 1·2·3·5초를 선택할 수 있습니다. 기존에 저장한 주기는 유지합니다. SSD 저장공간은 별도의 체크 주기를 사용합니다.

모니터링 설정에서 네트워크·디스크 이름 옆의 작은 메뉴로 표시 기준을 선택합니다. 기본값은 `데이터`이며 네트워크는 `패킷`, 디스크는 `IO`로 바꿀 수 있습니다. 메뉴바·상세 그래프·툴팁에 함께 적용하고 재실행 후에도 유지합니다. 상세 제목 오른쪽에도 현재 기준을 표시하며 네트워크는 인터페이스 이름을 함께 표시합니다. 패킷은 `pkt/s`, 디스크 작업 횟수는 `IO/s`로 표시합니다. 기준 변경 시 해당 항목의 최근 기록을 새로 시작하며, 펼친 프로세스 목록은 기존 데이터량 기준을 유지합니다.

일반 항목의 그래프는 `자동 / 라인 / 바 / 게이지` 중 선택하며, 메모리는 `자동 / 바 / 게이지`를 제공합니다. SSD는 용량 바, 시스템 온도는 CPU·GPU 라인으로 고정됩니다. 기록은 메모리에 최근 5분만 보관하며, 재실행하면 초기화됩니다. 첫 측정·수집 실패·미지원 상태는 0으로 표시하지 않고 `—`와 안내로 구분합니다.

메모리의 자동·바 모드는 앱·Wired·압축·여유 구성 막대를 표시합니다. 게이지도 같은 네 색상과 비율로 구성하며 중앙 숫자는 전체 사용률입니다. 게이지의 색상 호에 마우스를 올리면 0.2초 뒤 이름·용량·비율 툴팁이 나타납니다. 툴팁은 포인터의 10pt 위를 따라 움직이며 팝업의 표시 영역 안으로 위치를 보정하고, 위쪽 공간이 부족하면 아래에 표시합니다. 구간 이동 시 즉시 갱신하고 중앙·빈 공간·게이지 이탈 시 숨깁니다. 기존 메모리 라인 설정은 자동으로 복구합니다. 구성 수치는 막대 아래에 표시하고, 게이지 모드에서는 게이지와 최근 5분 사용률 기록 아래에 표시합니다. 앱·Wired·압축·여유 항목의 색상 점과 용량이 범례를 겸하며, 막대에 마우스를 올리면 0.2초 후 막대 위쪽에 이름·용량·전체 메모리 대비 비율의 툴팁이 나타납니다. 다른 구간으로 이동하면 즉시 내용이 바뀌고 막대를 벗어나면 사라집니다. Swap은 기본적으로 RAM 구성 수치 아래에 `사용량 / 현재 할당량` 한 줄로 표시합니다. 모니터링 설정의 메모리 옵션에서 `Swap 상세`를 체크하면 별도 용량 바와 사용·할당 여유 용량을 표시합니다. 사용량은 청록색, 현재 할당된 공간 중 여유분은 회색입니다. 이 표시 선택은 재실행 후에도 유지하며 수집 설정에는 영향을 주지 않습니다. 할당량은 macOS가 자동으로 조절하는 현재 값이며 고정된 최대 한도가 아닙니다. RAM 구성 막대에는 포함하지 않으며, 기존 메모리 조회에서 함께 읽어 별도 수집 작업을 추가하지 않습니다. SSD 저장공간은 독립 항목으로 표시하며 모니터링 목록에서 순서를 바꿀 수 있습니다. RAM 그래프 형식과 관계없이 RAM과 같은 두께·모서리의 용량 막대와 색상 점이 있는 사용·남은 용량을 항상 표시합니다. SSD 사용은 파란색, 여유는 회색이며 각 구간의 용량·비율 툴팁도 RAM과 같은 위치·표시 시간을 사용합니다.

측정값은 다음 범위를 기준으로 합니다.

- **메모리:** 시스템 통계로 계산한 사용량 추정치입니다. ‘활성 상태 보기’와 측정 시점·집계 방식에 따라 차이가 날 수 있습니다. SSD 용량은 별도 항목에서 확인합니다.
- **디스크:** 시작 볼륨의 읽기·쓰기 속도만 측정합니다. 용량과 독립적으로 일반 갱신 주기를 따릅니다.
- **SSD:** 저장공간은 선택한 체크 주기로 갱신하며, macOS가 제거 가능한 공간까지 포함한 `volumeAvailableCapacityForImportantUsage`를 사용합니다. SSD 상세·메뉴바·용량 알림 모두 같은 기준을 사용합니다. 해당 값을 제공하지 않거나 유효하지 않으면 기본 여유 공간으로 대체합니다. 시스템 설정과는 갱신 시점에 따라 작은 차이가 날 수 있습니다.
- **네트워크:** 한 인터페이스만 측정합니다. VPN 트래픽은 설정에서 해당 인터페이스를 선택해 확인합니다.
- **GPU:** Intel 실행에서는 선택을 비활성화하고 수집·메뉴바·상세·GPU 알림에서 제외합니다. Apple Silicon도 기종·드라이버·macOS에 따라 전체 또는 프로세스 통계를 제공하지 않을 수 있습니다.
- **에너지:** 조회 가능한 프로세스의 추정 전력이며 Mac 전체 소비 전력이나 ‘활성 상태 보기’의 ‘에너지 영향’ 점수가 아닙니다. Intel 실행에서는 선택을 비활성화하고 수집·메뉴바·상세에서 제외합니다. Apple Silicon의 카운터 미지원 기기에서는 전력을 미지원으로 표시합니다.

## 사용법

한국어와 영어를 지원합니다. 설정 → `모니터링`의 로그인 설정 아래에서 `시스템 설정 따름 / 한국어 / English`를 선택할 수 있습니다. 기본값은 macOS 선호 언어를 따르며 지원하지 않는 언어에서는 영어를 사용합니다. 언어를 바꾸면 재시작 확인 팝업이 나타납니다. `지금 재시작`은 변경한 언어로 설정 창을 다시 열고, `나중에`는 선택을 저장한 채 현재 언어를 유지하다가 다음 실행에 적용합니다.

메뉴바 항목을 클릭해 상세 패널을 열고, 하단의 `설정…`에서 항목을 조절합니다. 바로 옆의 `활성 상태 보기` 버튼으로 macOS 앱을 열 수 있으며, 이미 실행 중이면 해당 앱을 앞으로 가져옵니다. 설정 창을 닫아도 모니터링은 계속됩니다.

설정 → `모니터링`에서 항목 켜기/끄기, 배치 순서, 그래프 형식, 갱신 주기(`1초 / 2초 / 3초 / 5초`), 네트워크 인터페이스를 선택합니다. 상세 패널은 내용에 맞춰 늘어나며, 화면의 사용 가능한 높이의 80%를 넘는 내용은 내부에서 스크롤합니다.

`SSD`는 메모리와 독립적으로 켜고 끄는 모니터링 항목입니다. 그래프 옵션 대신 체크 주기 `30초·1분·5분·10분·30분`을 선택하며 기본은 30초입니다. SSD를 끄면 용량 조회가 중단되고 디스크 I/O는 따로 유지됩니다. SSD만 켜져 있으면 기본 수집도 SSD 주기로 대기합니다. 상세에는 고정 용량 바와 저장 공간 관리 바로가기 버튼을 표시하고 기록 그래프·프로세스 목록은 제공하지 않습니다. 주기 변경과 잠자기 복귀 시 새 용량을 읽습니다. 팝업을 열 때마다 주기와 무관하게 추가 조회하지는 않습니다.

설정 → `메뉴바`의 `항목 그룹화`에서 CPU·RAM·SSD·GPU·에너지·시스템 온도 카드를 다른 항목 위로 드래그해 두 줄로 묶습니다. 드래그한 항목이 위, 대상 항목이 아래에 표시됩니다. 기존 그룹의 항목도 새 짝으로 바꿀 수 있으며 이전 짝은 개별 표시로 돌아갑니다. 그룹 안에서 다른 항목 위로 드래그하면 두 줄 순서를 교환하고, 그룹 밖의 해제 영역으로 꺼내거나 × 버튼을 누르면 해제합니다. Esc는 취소, 보조 클릭 메뉴는 같은 동작을 제공합니다. 네트워크·디스크 I/O는 제외하며 최대 세 그룹을 만들 수 있습니다. 드래그 중에는 반투명 카드·대상 강조·두 줄 미리보기만 표시하고 마우스를 놓았을 때 저장합니다.

그룹 클릭 시 두 상세가 함께 열리고 한쪽 모니터링을 끄면 나머지만 한 줄로 표시합니다. 그룹 설정은 유지되며 통합·항목별 모드 모두 적용됩니다. 메뉴바 그룹 위치·표시 우선순위는 기존 배치·우선순위 설정을 따릅니다. 새 설치 기본값은 RAM/SSD 그룹만 사용하며 기존 CPU/GPU·RAM/SSD 선택과 순서는 그대로 이전됩니다. 미지원 기기의 GPU·에너지·시스템 온도는 묶기 조작을 비활성화하지만 저장된 그룹은 유지합니다. 기존 메모리 옆 SSD 선택·체크 해제·전체 비활성·디스크 용량 알림의 SSD 이전도 유지합니다.

설정 탭은 `모니터링 → 알림 → 메뉴바` 순서입니다. 모니터링 목록은 `아이콘 → 체크박스·이름 → 그래프 → 형식 선택 → 드래그 손잡이`를 한 줄에 배치합니다. 미지원 항목의 설명은 행 아래에 표시합니다.

### 메뉴바 표시

설정 → `메뉴바`에서 표시 방식과 범위를 선택합니다.

`RAM / SSD 표시 값`은 RAM·SSD 두 줄로 구성합니다. 각 줄에서 사용 용량·남은 용량을 선택하고, 옆의 `%로 표시`를 체크하면 선택한 용량을 전체 대비 비율로 표시합니다. 기본은 RAM 사용 용량 + % 표시와 SSD 남은 용량 + 용량 단위 표시입니다. 기존 표시 설정도 유지됩니다. RAM 옆 작은 점은 macOS가 제공하는 메모리 압력 상태로 녹색 정상·노란색 주의·빨간색 부족·회색 확인 불가를 표시하며, 메뉴바 도움말에서도 상태를 확인할 수 있습니다. 사용률로 압력을 추정하지 않습니다. RAM 남은 용량은 전체−현재 사용량이며 앞으로 압축·회수 가능한 모든 메모리를 의미하지 않습니다. RAM 용량은 GiB/MiB를 사용합니다. SSD 메뉴바 용량은 GB/TB를 기본으로, 1 GB 미만이면 MB 등 작은 단위를 사용합니다. 선택된 단위에서 100 이상은 정수, 100 미만은 소수점 한 자리로 절삭하며 상세 용량 형식은 유지합니다. 표시 값은 그룹화 여부와 관계없이 적용하고, 설정 변경은 수집·알림 기준에 영향을 주지 않습니다.

SSD 남은 용량·비율의 수치 끝에는 RAM 압력 점과 같은 크기의 청록색 채운 점을 표시합니다. 사용 용량·사용률에는 점을 표시하지 않습니다. 점 표시 여부는 `%로 표시` 체크와 관계없이 사용/남은 용량 선택을 따릅니다. 그룹에서는 위 RAM·아래 SSD 점의 끝 위치를 맞춥니다.

알림의 기준과 유지 시간을 충족해 활성 경고가 생기면 해당 수치와 단위를 빨간색으로 표시하고 기존 `!`도 유지합니다. 그룹·통합에서도 경고 항목만 강조하며 경고가 해제되면 기본 색으로 복귀합니다. RAM 압력 점은 알림 설정과 독립적입니다.

- **항목별 표시(기본):** 각 항목을 따로 표시하고, 클릭한 항목의 상세를 엽니다.
- **통합 표시:** 활성 항목을 한 칸에 모으고, 클릭하면 전체 상세를 엽니다.

모니터링 탭의 순서는 메뉴바의 왼쪽→오른쪽 배치와 전체 상세 순서를 정합니다. 통합 표시와 전체 상세는 그룹과 관계없이 모니터링 목록 순서를 그대로 따릅니다. 항목별 메뉴바 그룹을 클릭한 상세는 해당 그룹의 위→아래 순서로 표시합니다. 메뉴바 탭의 `표시 우선순위`는 공간이 부족할 때 남길 항목을 정하며 배치 순서와 별도로 저장합니다.

두 목록 모두 오른쪽 손잡이를 드래그해 순서를 바꿉니다. 이동 중에는 행 전체 미리보기와 점선 빈 자리를 표시하고 주변 행이 부드럽게 이동합니다. 드롭 후 빈 자리에 안착하면 저장하며, 이동 중에는 실제 메뉴바 순서를 바꾸지 않습니다. `Esc` 또는 목록 밖 드롭으로 취소할 수 있습니다. 손잡이 우클릭 메뉴와 접근성 위/아래 이동도 제공합니다. 시스템의 동작 줄이기 설정에서는 애니메이션을 생략합니다.

실제 메뉴바의 개별 항목은 ⌘ 키를 누른 채 드래그해 위치를 옮길 수 있습니다. 재실행하거나 그룹화·표시 항목 구성을 변경하면 모니터링 탭의 배치 순서를 다시 적용합니다.

설정 창과 업데이트 팝업의 버튼은 흰색 기본 배경에 마우스를 올리면 회색으로 강조됩니다. 설정 탭과 메뉴바 표시 방식·표시 범위의 버튼 그룹에도 hover 효과를 적용하며, 선택한 항목은 별도 배경으로 구분합니다. 이미 선택된 항목과 비활성 버튼에는 hover 강조를 표시하지 않습니다.

현재는 기존 커스텀 탭 스타일을 사용합니다. Liquid Glass 전환은 철회했으며 재검토는 보류 작업입니다.

| --- | --- |
| 자동 | 공간에 맞춰 낮은 우선순위 항목부터 숨기고, 공간이 확보되면 복원 |
| 일반(기본) | 활성 항목 전체 표시 |
| 축소 | 우선순위 상위 2개 표시 |
| 최소 | 우선순위 상위 1개 표시 |

묶인 두 항목은 표시 범위에서 1개로 계산합니다. 메뉴바 그룹 위치는 위쪽 항목의 모니터링 위치를 사용합니다. 그 그룹만 클릭한 상세는 위쪽 → 아래쪽 순서이고, 통합·전체 상세는 그룹과 무관하게 모니터링 목록 순서입니다. 공간 부족 시 남길 그룹은 두 항목 중 높은 표시 우선순위를 따르며 그룹 전체가 함께 숨겨지거나 복원됩니다.

자동은 **활성 설정 창이 있는 화면, 그 외에는 포인터가 있는 화면**의 메뉴바 공간을 기준으로 조절하며, 모든 메뉴바에는 같은 항목 구성을 표시합니다. 다른 앱의 긴 메뉴나 임의 배치에 따른 모든 가림을 감지하지는 못하므로 필요하면 축소·최소를 직접 선택합니다.

숨긴 항목도 계속 수집하며 전체 상세에서 확인할 수 있습니다. Lookout이 활성화된 상태에서 `모니터링 → 메뉴바 패널 열기` 또는 `⌘⇧M`으로 전체 상세를 엽니다.

상세 팝업 상단 오른쪽의 `창으로 분리` 아이콘을 누르면 현재 항목·그룹 또는 전체 상세를 독립 창으로 엽니다. 기존 팝업은 닫히고, 독립 창은 다른 곳을 클릭해도 유지되며 이동·최소화할 수 있습니다. 분리 창은 하나만 사용하고 기존 수집 데이터·기록을 공유합니다. 하단의 `닫기`와 `⌘W`는 해당 창만 닫으며 메뉴바 모니터링은 계속됩니다. `설정…`을 누르거나 설정 메뉴·단축키로 진입하면 분리 창을 먼저 닫고 설정 창을 엽니다. 최소화·닫기 시 해당 창의 그래프와 추가 프로세스 표시 작업은 중단됩니다.

### 프로세스 목록

SSD·시스템 온도를 제외한 여섯 항목의 `프로세스 · 최대 5개`에서 사용량이 큰 프로세스를 확인합니다. 항목별 표시에서는 기본 펼침, 통합 표시에서는 기본 닫힘이며 직접 접거나 펼칠 수 있습니다. 이름 위에 포인터를 올리면 전체 이름과 PID를 확인합니다.

이름 앞에는 작은 앱 아이콘을 표시하며, 앱을 확인할 수 없는 시스템 프로세스는 공통 아이콘을 사용합니다. 아이콘은 펼쳐진 목록에서만 조회하고 캐시해서 재사용합니다.

에너지의 `잠자기 방지`는 기본적으로 최대 3개 이름과 나머지 개수를 요약합니다. 제목 옆 화살표를 펼치면 아이콘과 이름으로 전체 목록을 표시합니다. 긴 이름은 줄바꿈하며 포인터를 올리면 PID도 확인할 수 있습니다. 이 목록은 에너지 사용량 상위 5개와 별개입니다.

접근 가능한 프로세스만 표시합니다. 프로세스 CPU는 코어 1개를 100%로 계산해 100%를 넘을 수 있습니다. 프로세스별 디스크·네트워크는 전체 디스크·인터페이스 기준으로, 상단 그래프의 측정 범위와 다릅니다. 프로세스 종료 기능은 제공하지 않습니다.

### 알림

설정 → `알림`에서 CPU·메모리·GPU 사용률, SSD 여유 공간, 시스템 온도의 기준값·지속 시간을 설정합니다. 처음에는 알림과 소리가 모두 꺼져 있으며, 처음 활성화할 때 macOS 알림 권한을 요청합니다. `테스트 알림`으로 연결을 확인할 수 있습니다.

시스템 온도 알림은 CPU·GPU 중 높은 온도를 기준으로 하며, 초기값은 90°C 이상 30초 유지입니다. 기준보다 5°C 낮은 상태가 10초 유지되면 해제합니다. 팬 설정·helper와 관계없이 동작하지만 시스템 온도 모니터링은 켜져 있어야 합니다. 기존 5초 이상 간격의 새 온도 샘플만 판단하므로 수집 작업이나 타이머를 추가하지 않습니다. 현재 지원 범위는 M1 Pro MacBook Pro이며 초기 온도 기준은 과열 진단을 뜻하지 않습니다.

같은 문제는 한 번만 알리고 정상 범위가 유지된 뒤 재발하면 다시 알립니다. 모니터링을 끄면 해당 항목의 알림 판단도 중단됩니다. SSD 용량 알림은 선택한 체크 주기의 새로운 용량 샘플로 판단하므로 긴 주기에서는 알림과 해제가 늦어질 수 있습니다. 실제 배너와 소리는 macOS 알림 설정·집중 모드를 따릅니다.

### 메뉴바 전체 아이콘 간격

설정 → `메뉴바` 하단에서 프리셋·슬라이더를 조절하고 `적용`을 누릅니다. 다른 앱을 포함한 메뉴바 전체에 영향을 주며, 변경 전 설정을 보관해 `원래 값으로 복원`할 수 있습니다. 다른 앱이 값을 변경했다면 복원 전에 선택을 요구합니다.

실제 화면 반영은 아직 미검증인 실험적 기능입니다. 설정 저장 직후의 반영을 보장하지 않으며 로그아웃 후 재로그인 등 추가 작업이 필요할 수 있습니다. 앱이 로그아웃·재부팅을 자동 실행하지는 않습니다. 앱을 삭제하기 전에 변경한 간격을 되돌리려면 먼저 복원하세요.

### 업데이트

설정 하단의 `업데이트…`에서 버전 확인과 `새 버전 자동으로 확인`을 설정합니다. Sparkle 기반이며 다운로드·설치·재실행은 사용자가 선택합니다.

기본 빌드는 [현재 GitHub 저장소](https://github.com/unknowm-computer/lookout)의 최신 Release에서 `appcast.xml`을 읽습니다. 주소와 Ed25519 공개 키는 `Resources/UpdateConfiguration.json`에 보관하고 앱의 Info.plist에 포함합니다. 개인 키는 배포 Mac의 키체인에만 보관합니다. 별도 서버나 고정 IP는 필요하지 않습니다.

[Lookout 0.6.3a Release](https://github.com/unknowm-computer/lookout/releases/tag/v0.6.3a)에서 배포 파일과 업데이트 피드를 제공합니다. GitHub 피드·공개 키가 포함된 0.6.0·0.6.1·0.6.2·0.6.3 앱은 앱 안에서 0.6.3a (build 10)로 업데이트할 수 있습니다. 업데이트 설정이 없던 기존 앱은 이번 DMG로 한 번 수동 설치합니다. 자동 확인은 기본 꺼짐이며 설치는 사용자가 선택합니다. Apple Silicon·macOS 27의 검증용 0.6.0 복사본에서 공개 GitHub 다운로드·앱 교체·0.6.1 재실행을 확인했습니다.

다음 배포의 표시 버전·내부 build를 먼저 증가시킨 뒤 아래 명령을 실행합니다. GitHub에 자동 업로드하지 않습니다.

```sh
python3 scripts/prepare-release.py
```

`build/releases/v<version>-build<build>/`에 `Lookout-<version>.zip`, `Lookout-<version>.dmg`, `appcast.xml`, `SHA256SUMS.txt`가 생성됩니다. ZIP은 Sparkle 업데이트용, DMG는 최초·수동 설치용입니다. 게시된 `v0.6.3a-build10` 폴더와 태그는 덮어쓰지 않습니다. 게시 방법과 다음 버전 준비는 [GitHub 업데이트 배포 안내](docs/UPDATE_RELEASE.md)를 따릅니다.

다른 배포 경로를 테스트하려면 `LOOKOUT_UPDATE_FEED_URL`과 `LOOKOUT_UPDATE_PUBLIC_KEY`를 함께 지정해 기본값을 덮어씁니다. 업데이트를 제외한 개발 빌드는 `LOOKOUT_DISABLE_UPDATES=1 bash scripts/build.sh`로 만듭니다. 배포 스크립트는 기본 GitHub 주소와 서명 키가 일치하는 빌드만 허용합니다.

## 빌드와 실행

Swift 6 및 macOS 15 이상 SDK가 있는 Xcode를 사용합니다. 스크립트는 `/Applications/Xcode.app`을 우선 사용하며, 다른 Xcode는 `DEVELOPER_DIR`로 지정합니다. 앱은 Swift·SwiftUI·AppKit으로 구현하고, 업데이트에는 Sparkle 2.10.0을 사용합니다. [Sparkle 라이선스](Resources/Sparkle-LICENSE.txt)는 앱에도 포함합니다.

```sh
bash scripts/build.sh
open build/Lookout.app
```

결과는 `build/Lookout.app`입니다. 앱·두 helper·Sparkle 실행 파일의 Universal 아키텍처와 중첩 서명을 검사합니다. helper는 최초 설정 복구 전에는 자동 등록하지 않으며, 공증된 배포 앱은 아닙니다.

helper 동작 코드는 `FanSupport`·`WindowLayoutModel`·`WindowLayoutRuntime`으로 분리되어 앱의 UI·번역 변경에 영향을 받지 않습니다. `scripts/package-helpers.py`는 helper 및 모든 로컬 의존 소스·실행 plist·전용 리소스·빌드 설정·도구 버전을 비교하고, 같으면 `.helper-artifacts/`의 **기존 서명된 결과물을 그대로 재사용**합니다. 복사 전후 서명과 캐시 무결성을 검사합니다. 이 폴더는 Git에 함께 보관해 다른 Mac에서도 동일한 서명 결과물을 가져옵니다. `.gitattributes`로 줄바꿈 변환을 막고 Git의 실행 권한 기록도 함께 보존합니다. helper 소스·빌드 설정·Xcode/Swift/SDK 버전 등 입력이 같을 때만 재사용하며, 입력이 다르거나 캐시가 없는 환경에서는 새 helper를 만들기 때문에 동일 서명·권한 유지까지 보장하지는 않습니다. 별도 캐시는 `LOOKOUT_HELPER_CACHE`로 지정할 수 있습니다.

이번 모듈 분리로 helper 자체가 바뀌는 최초 업데이트에는 재설정·재승인이 필요할 수 있습니다. 이후 UI만 바뀌는 빌드에서는 helper 신원을 유지합니다. macOS가 본체의 백그라운드 승인을 다시 요구하는 경우까지 차단하지는 않으며, 실제 OS 상태와 AX 접근 결과를 계속 확인합니다.


설치 용량을 줄이기 위해 앱 실행 파일의 로컬·디버그 심볼을 제거합니다. 기능·Swift 런타임 메타데이터·두 아키텍처는 유지하며, 크래시 분석용 심볼은 `build/Lookout.app.dSYM`에 별도로 보관합니다. dSYM은 앱이나 DMG에 포함하지 않습니다.

설정 창으로 새로 실행하려면 다음 명령을 사용합니다.

```sh
open build/Lookout.app --args --settings
```

이미 실행 중이고 창이 모두 닫혀 있다면 앱을 다시 열어 설정 창에 접근할 수 있습니다. CLI 인자는 새로 실행할 때 적용됩니다.

## 로그인 시 자동 실행

설정 → `모니터링` 상단에서 `로그인 시 자동 실행`을 켜면 macOS 로그인 항목에 Lookout을 등록하고, 끄면 등록을 해제합니다. 처음 설치한 앱은 자동으로 등록하지 않습니다. 기존 등록이 있으면 macOS의 실제 상태를 표시합니다.

DMG에서 `/Applications/Lookout.app`으로 설치한 앱에서 설정하세요. 개발 빌드나 DMG 안의 앱을 등록하면 해당 앱의 경로를 옮기거나 삭제할 때 자동 실행이 안 될 수 있습니다. `로그인 항목 열기` 버튼으로 시스템 설정을 열어 등록을 확인할 수 있습니다. 승인 필요 상태에서는 macOS에서 Lookout을 허용해야 자동 실행됩니다. 등록 상태는 설정 화면을 열거나 돌아올 때와 앱에서 등록·해제를 변경한 뒤 확인하며, 지속적으로 조회하지 않습니다.

확인은 앱을 종료한 뒤 로그아웃·로그인하여 진행합니다. 로그인 화면이 표시되기 전부터 동작하는 시스템 서비스는 아닙니다. 로그인 후 ‘활성 상태 보기’에서 Lookout 프로세스를 찾거나 다음 명령으로 실행 여부와 앱 경로를 확인할 수 있습니다. 결과가 없으면 실행 중인 Lookout 프로세스가 없는 상태입니다.

```sh
pgrep -fl '/Lookout.app/Contents/MacOS/Lookout'
```

메뉴바에서 보이지 않아도 프로세스가 있다면 노치·메뉴바 공간 때문에 가려진 것인지 확인합니다. 관련 설정 절차는 [Apple 로그인 항목 안내](https://support.apple.com/ko-kr/guide/mac-help/mh15189/mac)를 참고하세요.

## DMG 만들기

```sh
bash scripts/create-dmg.sh
```

현재 소스로 앱을 빌드한 뒤 `build/Lookout-0.6.3a.dmg`을 생성합니다. 파일명의 버전은 앱의 `CFBundleShortVersionString`을 따릅니다. 같은 버전으로 다시 만들면 기존 DMG를 교체합니다.

DMG에는 `Lookout.app`, `Applications` 바로가기, `Install Lookout.command`, `설치 안내.txt`가 들어갑니다. 개인용 설치 스크립트는 새 앱의 서명을 검사하고, 설치 위치의 실행 중인 Lookout을 종료한 뒤 교체합니다. 실패 시 보관한 기존 앱을 복구하며 설치가 끝나면 새 앱을 실행합니다.

### 개인용 설치·수정 버전 업데이트

DMG를 열고 터미널에서 다음을 실행합니다. 내려받은 `.command` 파일 자체도 차단될 수 있으므로 터미널 실행을 기준으로 안내합니다.

```sh
/bin/bash "/Volumes/Lookout/Install Lookout.command"
```

DMG가 다른 이름으로 열렸다면 터미널에 `/bin/bash `를 입력하고 DMG 안의 `Install Lookout.command`를 터미널로 드래그한 뒤 Return을 누릅니다. 새 설치와 업데이트 모두 같은 명령을 사용합니다.

스크립트는 `/Applications/Lookout.app`으로 설치한 앱의 `com.apple.quarantine` 속성만 제거합니다. 원본 앱·DMG·다른 확장 속성·다른 앱·Mac 전체 보안 설정은 변경하지 않습니다. 이 처리는 Developer ID 서명·공증을 대신하지 않으며 직접 만들거나 신뢰하는 사람이 전달한 Lookout에 사용합니다.

설치 폴더의 쓰기 권한이 부족하면 `--user`를 붙여 `~/Applications/Lookout.app`에 설치할 수 있습니다. 관리자 권한을 자동으로 요청하지 않습니다. 이 옵션은 기존 `/Applications`의 앱을 교체하지 않으므로 중복 앱과 로그인 항목 등록을 확인해야 합니다. 업데이트는 기존과 동일한 경로에서 진행하는 것을 권장합니다.

```sh
/bin/bash "/Volumes/Lookout/Install Lookout.command" --user
```

Finder에서 앱을 `Applications`로 드래그하고 `대치`하는 기존 설치도 가능합니다. 이 경우 실행 중인 앱은 직접 종료해야 하며 격리 속성은 처리하지 않습니다.

같은 Bundle ID의 앱만 교체하면 기존 모니터링·그래프·알림·메뉴바 설정은 유지됩니다. 최근 5분 기록과 프로세스 펼침 상태는 메모리 데이터이므로 재실행 시 초기화됩니다. 개발 중에는 DMG 없이 `build/Lookout.app`을 응용 프로그램 폴더에 복사해 교체해도 됩니다. 개발 폴더에서 새 앱을 실행하는 것만으로 기존 `/Applications/Lookout.app`이 갱신되지는 않습니다.

배포 DMG에는 개인 사용용 ad-hoc 서명 앱이 들어갑니다. 현재 작업본의 최근 변경으로 DMG를 다시 만들거나 게시하지는 않았습니다. 개인·소규모 지인 배포는 위 설치 스크립트를 사용하며, 일반 배포가 필요해지면 Developer ID 서명과 Apple 공증을 별도로 진행합니다. DMG 생성이나 설치 스크립트 추가만으로 공증·Sparkle 업데이트 배포 설정이 완료되지는 않습니다.

## 테스트와 검증

```sh
bash scripts/test.sh
python3 scripts/test-installer.py
python3 scripts/test-updates.py
build/Lookout.app/Contents/MacOS/Lookout --probe
build/Lookout.app/Contents/MacOS/Lookout --notification-status
build/Lookout.app/Contents/MacOS/Lookout --cooling-probe
```

`scripts/test.sh`는 Swift 테스트와 실제 하드웨어를 대체한 C SMC 테스트를 함께 실행합니다. 최신 통과 수와 실행 시점은 VALIDATION.md를 따릅니다.

`--probe`는 시스템 지표를 세 번 읽고 종료합니다. `--notification-status`는 알림 권한과 알림 센터에 남아 있는 Lookout 알림을 조회합니다. `--cooling-probe`는 지원 기기의 CPU·GPU 온도와 팬 상태를 읽습니다. 이 조회 명령들은 앱 설정·메뉴바 간격·팬 제어 모드를 변경하지 않습니다.

최신 검증 결과와 미검증 항목은 [VALIDATION.md](VALIDATION.md), 이전 변경별 기록은 [검증 이력](docs/VALIDATION_HISTORY.md)에 정리합니다.
