# Lookout

macOS의 ‘활성 상태 보기’에서 확인하는 시스템 상태와 프로세스 정보를 메뉴바에서 빠르게 볼 수 있는 앱입니다. 필요한 항목을 선택해 사용하고, 메뉴바 항목을 클릭해 상세 수치와 최근 그래프를 확인합니다.

현재 구현 기준: 2026-10-02 · 버전 `0.5.0` (build `5`). Swift·SwiftUI·AppKit 기반 macOS 네이티브 앱입니다.

## 지원 환경

- macOS Sequoia 15.0 이상
- Apple Silicon (`arm64`) + Intel (`x86_64`) Universal 앱

현재 실기기 실행 검증 환경은 Apple Silicon, macOS 27.0입니다. Intel 및 macOS 15·26에서의 실제 실행은 추가 확인이 필요합니다.

## 모니터링 항목

| 항목 | 표시 정보 | 자동 그래프 |
| --- | --- | --- |
| CPU | 전체 사용률 | 현재 사용률 게이지 + 최근 5분 기록 |
| 메모리 | 앱·Wired·압축·여유 메모리, swap | 누적 바 + 최근 5분 기록 |
| 디스크 | 시작 디스크 읽기·쓰기 속도, 사용량·전체·여유 공간 | 읽기·쓰기 라인 + 저장공간 바 |
| 네트워크 | 선택한 인터페이스의 업로드·다운로드 속도 | 업로드·다운로드 라인 |
| GPU | 전체·렌더링·타일링 사용률, 공유 메모리 | 현재 사용률 게이지 + 최근 5분 기록 |
| 에너지 | 프로세스 추정 전력(W), 소비 상위 프로세스, 잠자기 방지 프로세스 | 추정 전력 라인 |

최초 설치 시 Apple Silicon은 여섯 항목, Intel은 에너지를 제외한 다섯 항목이 활성화됩니다. 항목을 끄면 표시와 데이터 수집이 함께 중단되고, 모두 끄면 주기적 수집도 중단됩니다. 설정은 재실행 후에도 유지됩니다.

그래프는 `자동 / 라인 / 바 / 게이지` 중 선택합니다. 기록은 메모리에 최근 5분만 보관하며, 재실행하면 초기화됩니다. 첫 측정·수집 실패·미지원 상태는 0으로 표시하지 않고 `—`와 안내로 구분합니다.

측정값은 다음 범위를 기준으로 합니다.

- **메모리:** 시스템 통계로 계산한 사용량 추정치입니다. ‘활성 상태 보기’와 측정 시점·집계 방식에 따라 차이가 날 수 있습니다.
- **디스크:** 시작 볼륨의 읽기·쓰기만 측정합니다. 저장공간은 30초마다 갱신하며, macOS 저장 공간 설정의 회수 가능 공간을 포함한 값과 다를 수 있습니다.
- **네트워크:** 한 인터페이스만 측정합니다. VPN 트래픽은 설정에서 해당 인터페이스를 선택해 확인합니다.
- **GPU:** 기종·드라이버·macOS에 따라 전체 또는 프로세스 통계를 제공하지 않을 수 있습니다.
- **에너지:** 조회 가능한 프로세스의 추정 전력이며 Mac 전체 소비 전력이나 ‘활성 상태 보기’의 ‘에너지 영향’ 점수가 아닙니다. Intel 실행에서는 선택을 비활성화하고 수집·메뉴바·상세에서 제외합니다. Apple Silicon의 카운터 미지원 기기에서는 전력을 미지원으로 표시합니다.

## 사용법

메뉴바 항목을 클릭해 상세 패널을 열고, 하단의 `설정…`에서 항목을 조절합니다. 바로 옆의 `활성 상태 보기` 버튼으로 macOS 앱을 열 수 있으며, 이미 실행 중이면 해당 앱을 앞으로 가져옵니다. 설정 창을 닫아도 모니터링은 계속됩니다.

설정 → `모니터링`에서 항목 켜기/끄기, 배치 순서, 그래프 형식, 갱신 주기(`1초 / 2초 / 5초`), 네트워크 인터페이스를 선택합니다. 상세 패널은 내용에 맞춰 늘어나며, 화면의 사용 가능한 높이의 80%를 넘는 내용은 내부에서 스크롤합니다.

설정 탭은 `모니터링 → 알림 → 메뉴바` 순서입니다. 모니터링 목록은 `아이콘 → 체크박스·이름 → 그래프 → 형식 선택 → 드래그 손잡이`를 한 줄에 배치합니다. 미지원 항목의 설명은 행 아래에 표시합니다.

### 메뉴바 표시

설정 → `메뉴바`에서 표시 방식과 범위를 선택합니다.

- **항목별 표시(기본):** 각 항목을 따로 표시하고, 클릭한 항목의 상세를 엽니다.
- **통합 표시:** 활성 항목을 한 칸에 모으고, 클릭하면 전체 상세를 엽니다.

모니터링 탭의 순서는 메뉴바의 왼쪽→오른쪽 배치와 상세 표시 순서를 정합니다. 메뉴바 탭의 `표시 우선순위`는 공간이 부족할 때 남길 항목을 정하며 배치 순서와 별도로 저장합니다.

두 목록 모두 오른쪽 손잡이를 드래그해 순서를 바꿉니다. 이동 중에는 행 전체 미리보기와 점선 빈 자리를 표시하고 주변 행이 부드럽게 이동합니다. 드롭 후 빈 자리에 안착하면 저장하며, 이동 중에는 실제 메뉴바 순서를 바꾸지 않습니다. `Esc` 또는 목록 밖 드롭으로 취소할 수 있습니다. 손잡이 우클릭 메뉴와 접근성 위/아래 이동도 제공합니다. 시스템의 동작 줄이기 설정에서는 애니메이션을 생략합니다.

실제 메뉴바의 개별 항목은 ⌘ 키를 누른 채 드래그해 위치를 옮길 수 있습니다. 설정 목록의 드래그와는 별도 동작입니다.

설정 창과 업데이트 팝업의 버튼은 흰색 기본 배경에 마우스를 올리면 회색으로 강조됩니다. 설정 탭과 메뉴바 표시 방식·표시 범위의 버튼 그룹에도 hover 효과를 적용하며, 선택한 항목은 별도 배경으로 구분합니다. 이미 선택된 항목과 비활성 버튼에는 hover 강조를 표시하지 않습니다.

현재는 기존 커스텀 탭 스타일을 사용합니다. Liquid Glass 전환은 철회했으며 재검토는 보류 작업입니다.

| 표시 범위 | 동작 |
| --- | --- |
| 자동 | 공간에 맞춰 낮은 우선순위 항목부터 숨기고, 공간이 확보되면 복원 |
| 일반 | 활성 항목 전체 표시 |
| 축소 | 우선순위 상위 2개 표시 |
| 최소 | 우선순위 상위 1개 표시 |

자동은 **활성 설정 창이 있는 화면, 그 외에는 포인터가 있는 화면**의 메뉴바 공간을 기준으로 조절하며, 모든 메뉴바에는 같은 항목 구성을 표시합니다. 다른 앱의 긴 메뉴나 임의 배치에 따른 모든 가림을 감지하지는 못하므로 필요하면 축소·최소를 직접 선택합니다.

숨긴 항목도 계속 수집하며 전체 상세에서 확인할 수 있습니다. Lookout이 활성화된 상태에서 `모니터링 → 메뉴바 패널 열기` 또는 `⌘⇧M`으로 전체 상세를 엽니다.

### 프로세스 목록

각 항목의 `프로세스 · 최대 5개`에서 사용량이 큰 프로세스를 확인합니다. 항목별 표시에서는 기본 펼침, 통합 표시에서는 기본 닫힘이며 직접 접거나 펼칠 수 있습니다. 이름 위에 포인터를 올리면 전체 이름과 PID를 확인합니다.

접근 가능한 프로세스만 표시합니다. 프로세스 CPU는 코어 1개를 100%로 계산해 100%를 넘을 수 있습니다. 프로세스별 디스크·네트워크는 전체 디스크·인터페이스 기준으로, 상단 그래프의 측정 범위와 다릅니다. 프로세스 종료 기능은 제공하지 않습니다.

### 알림

설정 → `알림`에서 CPU·메모리·GPU 사용률과 디스크 여유 공간의 기준값·지속 시간을 설정합니다. 처음에는 알림과 소리가 모두 꺼져 있으며, 처음 활성화할 때 macOS 알림 권한을 요청합니다. `테스트 알림`으로 연결을 확인할 수 있습니다.

같은 문제는 한 번만 알리고 정상 범위가 유지된 뒤 재발하면 다시 알립니다. 모니터링을 끄면 해당 항목의 알림 판단도 중단됩니다. 디스크 용량 알림은 30초 용량 갱신에 따라 판단합니다. 실제 배너와 소리는 macOS 알림 설정·집중 모드를 따릅니다.

### 메뉴바 전체 아이콘 간격

설정 → `메뉴바` 하단에서 프리셋·슬라이더를 조절하고 `적용`을 누릅니다. 다른 앱을 포함한 메뉴바 전체에 영향을 주며, 변경 전 설정을 보관해 `원래 값으로 복원`할 수 있습니다. 다른 앱이 값을 변경했다면 복원 전에 선택을 요구합니다.

실제 화면 반영은 아직 미검증인 실험적 기능입니다. 설정 저장 직후의 반영을 보장하지 않으며 로그아웃 후 재로그인 등 추가 작업이 필요할 수 있습니다. 앱이 로그아웃·재부팅을 자동 실행하지는 않습니다. 앱을 삭제하기 전에 변경한 간격을 되돌리려면 먼저 복원하세요.

### 업데이트

설정 하단의 `업데이트…`에서 버전 확인과 `새 버전 자동으로 확인`을 설정합니다. Sparkle 기반이며 다운로드·설치·재실행은 사용자가 선택합니다.

현재 기본 빌드는 배포 피드와 검증 키가 없어 `업데이트 배포 준비 중입니다.`를 표시하고 확인 기능을 비활성화합니다. 지금 수정 버전을 설치하려면 아래의 수동 교체 절차를 사용합니다.

배포용 빌드는 `LOOKOUT_UPDATE_FEED_URL`과 `LOOKOUT_UPDATE_PUBLIC_KEY`를 함께 지정합니다. 이 설정을 포함한 앱을 먼저 수동 설치한 뒤 후속 버전을 앱 안에서 확인할 수 있습니다. 실제 Lookout 업데이트 파일의 다운로드·설치·재실행은 아직 검증하지 않았습니다. 배포 조건은 [기능 명세](SPEC.md#8-업데이트와-빌드), 남은 준비는 [개발 계획](PLAN.md#3-다음-검증-작업)을 참고하세요.

## 빌드와 실행

Swift 6 및 macOS 15 이상 SDK가 있는 Xcode를 사용합니다. 스크립트는 `/Applications/Xcode.app`을 우선 사용하며, 다른 Xcode는 `DEVELOPER_DIR`로 지정합니다. 앱은 Swift·SwiftUI·AppKit으로 구현하고, 업데이트에는 Sparkle 2.10.0을 사용합니다. [Sparkle 라이선스](Resources/Sparkle-LICENSE.txt)는 앱에도 포함합니다.

```sh
bash scripts/build.sh
open build/Lookout.app
```

결과는 `build/Lookout.app`입니다. 두 아키텍처와 Sparkle 보조 실행 파일을 확인한 뒤 로컬 실행용 ad-hoc 서명을 적용합니다. 공증된 배포 앱은 아닙니다.

설정 창으로 새로 실행하려면 다음 명령을 사용합니다.

```sh
open build/Lookout.app --args --settings
```

이미 실행 중이고 창이 모두 닫혀 있다면 앱을 다시 열어 설정 창에 접근할 수 있습니다. CLI 인자는 새로 실행할 때 적용됩니다.

## 로그인 시 자동 실행

설정 → `모니터링` 상단에서 `로그인 시 자동 실행`을 켜면 macOS 로그인 항목에 Lookout을 등록하고, 끄면 등록을 해제합니다. 처음 설치한 앱은 자동으로 등록하지 않습니다. 기존 등록이 있으면 macOS의 실제 상태를 표시합니다.

DMG에서 `/Applications/Lookout.app`으로 설치한 앱에서 설정하세요. 개발 빌드나 DMG 안의 앱을 등록하면 해당 앱의 경로를 옮기거나 삭제할 때 자동 실행이 안 될 수 있습니다. `로그인 항목 열기` 버튼으로 시스템 설정을 열어 등록을 확인할 수 있습니다. 승인 필요 상태에서는 macOS에서 Lookout을 허용해야 자동 실행됩니다. 시스템 설정에서 변경한 상태도 앱 설정에 다시 반영됩니다.

확인은 앱을 종료한 뒤 로그아웃·로그인하여 진행합니다. 로그인 화면이 표시되기 전부터 동작하는 시스템 서비스는 아닙니다. 로그인 후 ‘활성 상태 보기’에서 Lookout 프로세스를 찾거나 다음 명령으로 실행 여부와 앱 경로를 확인할 수 있습니다. 결과가 없으면 실행 중인 Lookout 프로세스가 없는 상태입니다.

```sh
pgrep -fl '/Lookout.app/Contents/MacOS/Lookout'
```

메뉴바에서 보이지 않아도 프로세스가 있다면 노치·메뉴바 공간 때문에 가려진 것인지 확인합니다. 관련 설정 절차는 [Apple 로그인 항목 안내](https://support.apple.com/ko-kr/guide/mac-help/mh15189/mac)를 참고하세요.

## DMG 만들기

```sh
bash scripts/create-dmg.sh
```

현재 소스로 앱을 빌드한 뒤 `build/Lookout-0.5.0.dmg`을 생성합니다. 파일명의 버전은 앱의 `CFBundleShortVersionString`을 따릅니다. 같은 버전으로 다시 만들면 기존 DMG를 교체합니다.

DMG를 열고 `Lookout.app`을 `Applications` 바로가기로 드래그하면 설치할 수 있습니다. 기존 Lookout이 실행 중이면 종료한 뒤 교체하고, 응용 프로그램 폴더의 Lookout을 실행합니다. DMG는 앱을 담는 설치용 이미지이며 실행 중인 앱을 자동으로 교체하지 않습니다.

### 수정 버전 설치

1. 실행 중인 Lookout을 `종료`합니다.
2. 새 DMG를 열고 `Lookout.app`을 `Applications`로 드래그합니다.
3. 같은 이름의 앱이 있다는 안내에서 `대치`를 선택합니다.
4. `/Applications/Lookout.app`을 실행합니다.

같은 Bundle ID의 앱만 교체하면 기존 모니터링·그래프·알림·메뉴바 설정은 유지됩니다. 최근 5분 기록과 프로세스 펼침 상태는 메모리 데이터이므로 재실행 시 초기화됩니다. 개발 중에는 DMG 없이 `build/Lookout.app`을 응용 프로그램 폴더에 복사해 교체해도 됩니다. 개발 폴더에서 새 앱을 실행하는 것만으로 기존 `/Applications/Lookout.app`이 갱신되지는 않습니다.

현재 DMG에는 개인 사용용 ad-hoc 서명 앱이 들어갑니다. 다른 사람에게 배포할 때는 Developer ID 서명과 Apple 공증을 별도로 진행해야 합니다. DMG 생성만으로 서명·공증이나 Sparkle 업데이트 배포 설정이 완료되지는 않습니다.

## 테스트와 검증

```sh
bash scripts/test.sh
build/Lookout.app/Contents/MacOS/Lookout --probe
build/Lookout.app/Contents/MacOS/Lookout --notification-status
```

`--probe`는 시스템 지표를 세 번 읽고 종료합니다. `--notification-status`는 알림 권한과 알림 센터에 남아 있는 Lookout 알림을 조회합니다. 두 명령은 앱 설정이나 메뉴바 간격을 변경하지 않습니다.

최신 검증 결과와 미검증 항목은 [VALIDATION.md](VALIDATION.md), 이전 변경별 기록은 [검증 이력](docs/VALIDATION_HISTORY.md)에 정리합니다.
