# Lookout 변경별 검증 이력

기록 기간: 2026-10-02. 이 파일은 변경 당시의 확인 결과를 보존한다. 후속 변경으로 대체된 구현과 철회된 시도도 포함하며, 현재 상태는 [VALIDATION.md](../VALIDATION.md)와 [SPEC.md](../SPEC.md)를 따른다.

특히 초기 Transferable 기반 정렬은 드래그 미리보기 방식으로 대체됐고, Liquid Glass 전환과 SDK 명시 링크 설정은 철회됐다. 초기 기록의 테스트 57개·등록 기능 없음·드래그 미확인은 당시 결과이며 현재 상태를 뜻하지 않는다. 현재 자동 테스트는 59개이며 두 설정 목록의 마우스 드래그와 목록 밖 드롭 취소를 확인했다.

## Intel 에너지 제외·자동 실행 상태 확인 (2026-10-02)

- `MonitoringCapabilities`를 설정 복원·활성화 변경·수집 경로에 적용했다. `x86_64`에서는 에너지 체크박스를 비활성화하고 미지원 문구를 표시한다. 이전 저장 설정에서 켜져 있어도 실행 구성에서 제외한다.
- 두 테스트로 에너지 제외 후 다른 선택·순서·갱신 주기·인터페이스 유지와 에너지 Collector 호출 금지를 확인했다. 전체 57개 테스트가 통과했다.
- Universal 빌드와 DMG 생성·체크섬 검증이 성공했다. 이 호스트에서 `arch -x86_64 ... --probe`는 `Bad CPU type in executable`로 종료되어 Intel 실기기·UI 검증은 수행하지 못했다.
- 코드에 로그인 항목 등록 기능이 없으며 이 개발 Mac의 `sfltool dumpbtm`에서도 Lookout 등록 항목이 조회되지 않았다. 다른 Mac의 등록 상태는 확인하지 않았다. 재부팅·로그아웃이나 로그인 항목 추가는 실행하지 않았다.
- 로그인 항목 수동 등록과 재로그인 후 프로세스 확인 절차를 README에 추가했다.

## 로그인 시 자동 실행 구현·실기기 확인 (2026-10-02)

- 이전 확인 이후 모니터링 설정 상단에 `로그인 시 자동 실행`과 `로그인 항목 열기`를 추가했다. `SMAppService.mainApp`으로 등록·비동기 해제·실제 상태 조회를 수행한다.
- 실제 네이티브 UI에서 체크박스 켜기 → 등록 안내, macOS 로그인 시 열기 목록의 Lookout 행, `sfltool dumpbtm`의 `enabled, allowed` 등록을 확인했다.
- macOS에서 Lookout의 백그라운드 허용을 끈 상태에서는 앱이 승인 필요 안내를 표시했다. 허용 상태는 복원했고, 설정 중 늦게 반영되는 변경도 조회하도록 2초 상태 갱신을 추가했다.
- 최종 빌드에서 등록·해제를 다시 실행하고 체크박스가 꺼짐으로 복귀하는 것을 확인했다. 검증용 등록은 해제했으며 앱 설정 창을 열어 두었다.
- 자동 테스트 57개, Universal 빌드, 중첩 서명 검증, DMG 생성·체크섬 검증이 통과했다. 실제 재로그인·재부팅 후 자동 시작과 Intel/macOS 15·26 실기기 실행은 검증하지 않았다.

## 활성 상태 보기 바로가기 (2026-10-02)

- 상세 패널 하단 `설정…` 오른쪽에 텍스트·아이콘 버튼을 추가했다. `NSWorkspace`로 `com.apple.ActivityMonitor`를 찾아 열고 기존 실행 인스턴스를 사용한다.
- 실제 메뉴바 팝업의 전체 상세와 개별 상세에서 버튼을 확인하고, 버튼 클릭 후 활성 상태 보기 창을 확인했다. 실행 전후 PID 1658이 유지되어 기존 앱을 사용한 것을 확인했다.
- Universal 빌드, 중첩 앱 서명과 DMG 체크섬 검증이 통과했다. 실행 중이 아닌 활성 상태 보기의 최초 실행과 실행 실패 안내는 강제로 재현하지 않았다.

## 하단 버튼 기본 스타일 복원 (2026-10-02)

- `설정…`·`활성 상태 보기`·`종료`에 적용했던 `.plain`을 `.bordered`·`.controlSize(.small)`로 변경하고 고정된 secondary 글자색을 제거했다. 상태 피드백은 macOS의 기본 버튼 스타일에 맡긴다.
- 새 앱을 재실행하여 실제 메뉴바 팝업 하단에서 세 버튼의 기본 배경과 정상 배치를 확인했다. 포인터 이동에 따른 hover 전후 비교는 UI 상태 변경으로 완료하지 못했다.
- Universal 빌드·중첩 서명·DMG 생성과 이미지 체크섬 검증이 통과했다.

## 하단 버튼 흰색·hover 회색 조정 (2026-10-02)

- 이전 `.bordered`의 상시 회색 배경을 제거하고 공통 `PanelActionButtonStyle`을 적용했다. 라이트 모드에서 흰색 기본 배경 위에 hover 10%·눌림 20% 강조를 표시한다. 각 버튼이 별도로 hover 상태를 보관하며 비활성·사라짐 시 초기화한다.
- 앱을 재실행해 실제 메뉴바 팝업 하단의 세 버튼이 흰색으로 표시되는 것을 확인했다. 자동 포인터 이동은 CUA의 `windowNotFoundAtPosition` 오류로 완료하지 못해 hover 전후·다크 모드·키보드 포커스의 실제 화면 비교는 미검증이다.
- Universal 빌드, 중첩 서명과 DMG 체크섬 검증이 통과했다.

## 설정 hover·드래그 정렬 (2026-10-02)

- 설정 창과 업데이트 팝업에 공통 버튼 스타일을 적용했다. 간격 `적용`은 accent 배경을 유지하며 hover·눌림 강조를 추가했다. 체크박스와 Picker의 네이티브 스타일은 유지한다.
- 두 순서 목록은 공통 `MetricReorderRow`를 사용한다. 손잡이만 드래그를 시작하고 행 전체가 드롭을 받는다. 배치와 우선순위 payload를 구분하고, 유효한 드롭에서만 저장한다. macOS 15에서 사용할 수 있는 Transferable 기반 API를 사용한다.
- 다중 행 이동의 삽입·항목 보존·유효하지 않은 이동 무시와 우선순위 선택 시 배치·수집 설정 유지 테스트를 추가했다. 전체 59개 테스트가 통과했다.
- 실제 설정 창에서 손잡이 접근성 이동으로 배치와 우선순위가 변경되는 것을 확인했다. 우선순위 변경 중 현재 6개 표시의 배치 순서가 유지되었으며 UserDefaults의 독립 우선순위 저장을 확인했다. 두 목록은 검증 전 순서로 복원했고 최종 앱을 다시 실행했다.
- 실제 화면에서 손잡이와 설정·알림 버튼의 흰색 배경을 확인했다. CUA 드래그 호출은 순서 변경으로 이어지지 않아 마우스 드래그와 hover 전후 전환은 검증 완료로 판단하지 않는다. 접근성 이동 검증을 드래그 성공 근거로 사용하지 않는다.
- 최종 Universal 빌드, 중첩 서명, DMG 생성·체크섬 검증이 통과했다. Intel/macOS 15 실기기·다크 모드·키보드 포커스는 별도 검증이 필요하다.

## 설정 탭·버튼 그룹 hover (2026-10-02)

- 상단 모니터링/알림/메뉴바 탭과 메뉴바 표시 방식·범위를 공통 `HoverSegmentedPicker`로 교체했다. 각 버튼은 독립 hover 상태를 갖고 선택 배경·눌림 강조·포커스 테두리·접근성 선택 상태를 제공한다. 좌우 이동은 해당 그룹에만 적용한다.
- 실제 설정 창에서 모니터링 → 알림 → 메뉴바 전환과 선택 상태·내용 변경을 확인했다. 표시 범위 축소 선택 시 현재 2개, 일반 복원 시 6개로 갱신되는 것을 확인하고 기존 일반 설정으로 복원했다.
- Universal 빌드·서명·DMG 생성과 체크섬 검증이 통과했다. 마우스 hover 전후·다크 모드·키보드 이동은 자동 UI 검증으로 확인하지 못했다.

## 선택된 탭의 추가 강조 제외 (2026-10-02)

- `SegmentButtonBody.highlightOpacity`가 이미 선택된 항목에는 항상 0을 반환하도록 변경했다. 기존 선택 배경과 접근성·포커스 표시는 유지하고 hover·눌림 회색 강조만 제외한다. 상단 탭과 메뉴바의 두 버튼 그룹에 함께 적용한다.
- Universal 빌드·서명·DMG 체크섬 검증을 완료하고 앱을 다시 실행했다. 실제 포인터 hover 전후 비교는 수행하지 않았다. Liquid Glass 전환은 이 수정에 포함하지 않았다.

## 기본 컨트롤·Liquid Glass 전환 (2026-10-02)

- 커스텀 `HoverSegmentedPicker`와 버튼별 hover·포커스·키보드 처리를 제거하고 `NativeSegmentedPicker`로 교체했다. 상단은 macOS 27 이상에서 공개 `.tabs` 스타일을, 이전 OS에서는 `.segmented`를 사용한다. 메뉴바 두 옵션 그룹은 값 선택용 `.segmented`를 사용한다.
- 최초 빌드에서는 SDK 27로 컴파일했지만 실행 파일의 `LC_BUILD_VERSION.sdk`가 15로 기록됐다. 빌드 스크립트에서 `-platform_version macos 15.0 <현재 SDK>`를 명시하고 두 아키텍처의 최소 OS·SDK 기록을 확인하도록 추가했다. 최종 `vtool` 출력은 두 아키텍처 모두 최소 OS 15.0·SDK 27.0이다.
- macOS 27 실제 설정 창에서 기본 탭 그룹·선택 표시를 확인했고 모니터링 → 알림 → 메뉴바 전환이 정상 동작했다. 메뉴바 축소 2개 → 최소 1개 갱신과 항목별/통합 모드 변경도 확인하고 검증 직전 최소·통합 설정으로 복원했다.
- Universal 빌드·중첩 서명·DMG 생성·체크섬 검증이 통과했다. macOS 15·26 실행, Intel 실행, 다크 모드·포인터 이동 중 유리 효과·키보드 조작은 별도 실기기 검증이 필요하다.
- 최신 SDK 기록으로 링크한 앱의 `--probe`가 정상 종료했고 디스크·저장공간·프로세스 추정 전력·GPU 값의 수집을 확인했다. 로그는 `build/native-picker-probe.log`에 보관한다.

## Liquid Glass 전환 되돌림 (2026-10-02)

- 사용자 피드백에 따라 위 Liquid Glass 전환을 철회했다. `NativeSegmentedPicker`와 `.tabs` 분기를 제거하고 전환 직전의 `HoverSegmentedPicker`를 복원했다. 선택된 항목의 hover·눌림 강조 제외, 일반 버튼 hover, 드래그 정렬은 유지한다.
- 기본 선택 컨트롤 전반의 디자인도 바뀌게 했던 빌드 스크립트의 SDK 명시 플래그와 검증 코드를 제거했다. 두 아키텍처의 `vtool` 출력은 전환 전과 같은 `minos 15.0`, `sdk 15.0`으로 복원됐다.
- Universal 빌드·중첩 서명·DMG 생성·체크섬 검증이 통과했다. 앱을 다시 실행하고 실제 설정 창에서 전체 너비의 커스텀 탭·흰색 선택 배경·기존 체크박스와 그래프 드롭다운의 모양 복원을 확인했다.
- 저장 설정·수집 로직·드래그 정렬은 수정하지 않았다. hover 전후·다크 모드·키보드 조작·다른 OS 실기기를 새로 검증하지 않았다.

## 모니터링 목록 한 줄 배치 (2026-10-02)

- 아이콘·체크박스·이름·그래프 라벨·형식 선택·드래그 손잡이를 한 줄로 배치했다. 이름은 잘리지 않게 유지하고 그래프 선택 너비는 110pt, 손잡이는 행 중앙으로 맞췄다. Intel 미지원 설명은 해당 행 아래에 유지한다.
- 실제 설정 창에서 CPU·메모리·GPU·네트워크·디스크의 한 줄 배치와 가장 긴 네트워크 이름이 잘리지 않는 것을 확인했다. 에너지 행의 화면 확인과 Intel 실기기 확인은 수행하지 않았다. 기존 선택·드래그 동작은 변경하지 않았으며 이번 검증에서 실제 드래그 성공을 확인하지 않았다.
- Universal 빌드·중첩 서명·DMG 생성·체크섬 검증과 `git diff --check`가 통과했다. 앱을 다시 실행했다. 레이아웃 변경에 대한 별도 자동 테스트는 추가하지 않았다.
- Liquid Glass 재검토를 PLAN.md의 미완료 후속 작업으로 기록했다. 현재 스타일은 유지한다.

## 설정 드래그 미리보기·이동 애니메이션 (2026-10-02)

- 두 설정 목록을 공통 `MetricReorderList`로 감쌌다. 손잡이에서 시작한 제스처 동안 행 전체 미리보기와 점선 빈 자리를 표시하고, 이웃 행은 0.18초 애니메이션으로 이동한다. 시작 시 행 크기를 보관해 이동 중 위치 측정으로 인한 흔들림을 피한다.
- 미리보기 순서는 목록의 임시 상태로 유지한다. 드롭 후 행이 빈 자리에 안착하면 실제 설정을 한 번 반영한다. 목록 밖 드롭·Esc·화면 이탈은 취소하며, 시스템 동작 줄이기 설정에서는 애니메이션을 생략한다. 우클릭과 접근성 이동은 유지했다.
- 실제 마우스 드래그로 모니터링 CPU를 여러 행 이동·원상 복구하고, 목록 밖에 놓으면 순서가 유지되는 것을 확인했다. 메뉴바 우선순위에서도 CPU를 네 번째로 이동한 뒤 첫 번째로 복원했다. 저장된 두 순서가 각각 검증 전 값이며 활성 항목·갱신 주기·그래프 선택이 유지되는 것을 확인했다.
- 기존 자동 테스트 59개, Universal 빌드·중첩 서명·DMG 생성·체크섬 검증이 통과했다. 최종 앱을 다시 실행했다. CUA는 누른 채 멈추는 API를 제공하지 않아 드래그 도중 미리보기·애니메이션의 프레임별 화면 비교는 수행하지 않았다. Esc 입력과 동작 줄이기·Intel 실기기는 별도 UI 검증이 필요하다.
